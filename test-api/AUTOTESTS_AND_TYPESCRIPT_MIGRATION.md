# Автотесты и переход с JavaScript на TypeScript

## Что такое автотесты

Автотесты — это программы, которые сами выполняют проверку кода и сообщают, соответствует ли результат ожиданию. Для API-тестов это обычно означает: отправить HTTP-запрос, проверить код ответа, тело, заголовки и побочные эффекты.

Автотесты помогают:

- быстро находить регрессии после изменений;
- проверять одинаковые сценарии при каждом запуске;
- документировать ожидаемое поведение API;
- безопаснее рефакторить код.

Тест должен быть независимым, воспроизводимым и проверять один понятный сценарий. Тесты, которые создают данные, должны работать в тестовом окружении и очищать данные после себя.

## Можно ли переписать тесты в TypeScript автоматически

Полностью и безопасно — нет. Инструменты могут автоматически переименовать файлы и преобразовать повторяющийся синтаксис, но не могут достоверно определить:

- точную форму ответа API;
- допустимые значения полей;
- типы данных, которые возвращают моки;
- корректность работы теста во время выполнения.

Поэтому автоматизация ускоряет перенос, но каждый изменённый тест нужно проверить: он должен пройти и проверку типов, и обычный запуск.

## Что потребуется

Для проекта на Node.js установите TypeScript, типы Node.js и раннер, который умеет запускать TypeScript-тесты:

```powershell
npm install --save-dev typescript tsx @types/node
```

Создайте `tsconfig.json` в корне проекта:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "types": ["node"]
  },
  "include": ["test-api/**/*.test.ts"]
}
```

Добавьте команды в `package.json`:

```json
{
  "scripts": {
    "test": "node --import tsx --test",
    "typecheck": "tsc --noEmit"
  }
}
```

`node --import tsx --test` запускает тесты, а `npm run typecheck` проверяет типы без создания JavaScript-файлов.

## Пример перевода теста

JavaScript-тест получает ответ без информации о его структуре:

```js
const user = await response.json();
assert.equal(user.id, 1);
```

В TypeScript опишите контракт, который ожидает тест:

```ts
interface User {
  id: number;
  name: string;
}

const user: User = await response.json();
assert.equal(user.id, 1);
assert.equal(typeof user.name, "string");
```

Аннотация `User` помогает редактору и компилятору, но сама по себе не проверяет данные, пришедшие по сети. Для важных API-контрактов добавьте проверку во время выполнения, например с помощью схемы валидации.

## Рекомендуемый порядок миграции

1. Включите TypeScript и выполните `npm run typecheck`.
2. Переносите тесты небольшими группами: `users.test.js` в `users.test.ts`.
3. Для каждого теста опишите типы ответов API, параметров и тестовых данных.
4. Типизируйте моки и переменные окружения; не заменяйте ошибки на `any`.
5. После каждой группы запускайте `npm test` и `npm run typecheck`.
6. Когда все тесты перенесены, удалите JavaScript-варианты файлов.

Если в проекте много однотипных тестов, для механических изменений можно использовать codemod. Его следует применять только к известному шаблону, просматривать diff и запускать проверки после каждого пакета изменений.
